# maid-atelier · 深海女仆工坊

DeepSeek Harness Web GUI 的深海女仆工坊皮肤：双女仆背景、深海蓝蕾丝界面与 Q 版侧栏。纯展示层客户端插件——`apply()` 设置 `data-dsh-maid-atelier-wj` 作用域、按亮/暗主题切换宫殿背景、以独立透明层挂载双女仆角色、装饰可折叠侧栏,并为加载/思考/工具运行状态预留稳定动画钩子。effect 销毁器还原全部 CSS/DOM 写入;不注入服务、不发出 Cordis 事件、不触达模型请求。

## 特性

- 双女仆工坊场景对话背景(亮/暗自动切换)
- 深海蓝、陶瓷白、长春花蓝、柔金构成的可热切换 UI 覆盖层
- Q 版侧栏角色与视口装饰、favicon
- 启动插件加载失败时，默认以左右独立的双女仆立绘装饰原生错误报告，支持窄屏重排，遵循现有立绘显示与时段设置。此效果依赖皮肤已成功执行；皮肤自身或内核尚未加载时保留原生页面。
- 双女仆与宫殿背景整层挂在**对话区(centerCol)内部**:随聊天区域尺寸自适应(右/下工作台推开聊天区时背景与女仆同步收缩,不再固定于视口),左女仆贴聊天区左下、右女仆贴右下,均位于聊天记录与输入器之下;聊天态与着陆页按比例切换构图
- **角色立绘由宿主扫描目录后经本机 HTTP 路由提供**：左女仆造型与右女仆图层不再内嵌进 client bundle，新增一套造型＝新增一个文件夹，**不用改代码、不用重新构建**。其余装饰素材（宫殿背景、花边、图标）仍内嵌为数据 URI
- **可选**的会话状态立绘:右女仆在思考/工具运行时、一轮结束、本轮出错各换一张造型;三张造型随包内置(默认开启),也可由使用方通过 `window.__dshMaidAtelierArtwork` 覆盖
- **目录驱动的左女仆造型**：造型 = `assets/maid-left/` 下的一个文件夹，五张按工作状态命名的图（待机/思考/工具执行/回答中/出错）。设置里的造型下拉由宿主实际发现的文件夹生成，**丢一个文件夹进去、刷新页面就会出现**；状态判定只用宿主自身的 DOM 契约，宿主改名时退回待机立绘

## 会话状态立绘（内置，默认开启）

皮肤可以从宿主自身的 `data-state` 信号判断会话此刻在做什么——思考行与工具行都带这个属性——进而在「思考/工具运行中」「一轮结束」「本轮出错或被中断」三种时机换掉**右女仆**的立绘。三种造型（思考 / 完成·开心 / 出错·泄气）**随包内置**，默认就开着；使用方也可以用自己的数据 URI 覆盖任意一态：

```js
window.__dshMaidAtelierArtwork = {
  thinking: 'data:image/webp;base64,...',
  done:     'data:image/webp;base64,...',
  failed:   'data:image/webp;base64,...',
}
```

在皮肤激活**之前**设好该对象即可覆盖（只覆盖给出的键）。到「设置 → 皮肤管理 → 深海女仆工坊」可以关闭 **按会话状态切换立绘**。思考与出错是即时切换，结束与出错后保持约 4.2 秒再回到原立绘，且只换右女仆那一个节点，销毁时还原原值。**自行提供的图片请先确认授权**，并遵守本皮肤的美术许可边界。

## 左女仆造型（按工作状态更换）

每套造型是 `assets/maid-left/` 下的一个文件夹，各含五张按工作状态命名的立绘。下表前
三套有完整生成记录，末尾三套是 2026-10-09 新增的衍生造型（生成来源见 `NOTICE`）：

| 造型 | 说明 |
| --- | --- |
| **冬日洋装**（默认） | 与右女仆内置的冬日立绘同套：毛领深蓝大衣 + 鲸鱼围裙 + 热可可 + 雪地靴 |
| **泳装（分体）** | 深蓝蕾丝比基尼 + 半透明白纱笼裙、金色脚链 |
| **浴衣（夏日祭）** | 深蓝浴衣 + 浅蓝鲸鱼浪花纹样 + 陶瓷白蕾丝领口与下摆 + 柔金 obi 腰带，木屐与鲸鱼团扇 |
| **成熟-和服** | 2026-10-09 新增（`assets/maid-left/成熟-和服/`） |
| **成熟版-泳装1** | 2026-10-09 新增（`assets/maid-left/成熟版-泳装1/`） |
| **竞速泳衣** | 2026-10-09 新增（`assets/maid-left/竞速泳衣/`） |

每一套都随会话此刻在做什么更换姿势与表情；判定全部来自宿主自身的 DOM 契约，宿主改写这些属性时退回待机立绘，而不是报错。下面表格的姿势措辞覆盖前三套，新造型由生成器另行产出，未逐字对齐：

| 状态 | 判定信号 | 泳装 / 冬日洋装 / 浴衣 |
| --- | --- | --- |
| 待机 | 以下都不成立 | 微笑挥手，一手叉腰 / 端着热可可站着 / 持鲸鱼团扇微笑，一手叉腰 |
| 思考 | 思考行仍在流式输出：`[data-variant='think'][data-state='running']` | 手指托腮，抬眼思考（三套一致） |
| 工具执行 | 有未结算的工具/命令行：`[data-state='running']` | 端着托盘 / 把热可可端起来，一手叉腰 / 端着饮品托盘，一手叉腰 |
| 回答中 | 助手正文仍在流式输出：`[data-streaming]` | 眨眼比 V，星光点点（三套一致） |
| 出错 | 本轮出现 `[data-state='error']` 或 `[data-state='stopped']` | 惊慌举手、冷汗 / 可可洒了的慌张 / 惊慌举手、冷汗，紧攥团扇 |

「设置 → 皮肤管理 → 深海女仆工坊」里：

- **左女仆造型**：`冬日洋装（与右女仆同套）`（默认）/ `泳装（分体）` / `浴衣（夏日祭）`，切换走配置热重载；
- **左女仆按工作状态切换立绘**：默认开。关闭后她固定为**当前所选造型**的待机立绘，不再跟随工作状态；造型切换依然生效（设置先于角色舞台创建，所以此时只会等舞台出现，不会去读工作状态属性）。（早期版本把整套安装都挂在开关下，于是关闭此项后造型下拉彻底失灵，她只剩创建舞台时那一张立绘，看起来就像「造型设置没用」。）

出错立绘保持约 4.2 秒再回到待机；进入出错状态时附一次很短的摇摆动画，`prefers-reduced-motion` 下自动关闭。游标只在状态或造型变化时写 `src` 与 `data-maid-left-state` 两处，销毁时还原原值并删除该属性。

想用自己的立绘替换当前造型的任意一态，在皮肤激活**之前**设置（只覆盖给出的键）：

```js
window.__dshMaidAtelierLeftArtwork = { think: 'data:image/webp;base64,...' }
```

前三套立绘的来源、生成提示词与绿幕抠像脚本见 `NOTICE` 与 `scripts/build-maid-left-state-art.py`；2026-10-09 新增的三套同样在 `NOTICE` 里署名（Qwen image 2.1，提示词由维护者保管）。生成结果的身份/服装/鲸鱼尾/画崩语义质检见 `scripts/review-maid-art.py`。

## 构建徽章（判断窗口是否已加载这一版）

皮肤是**版本化、不可变**的浏览器包。窗口一旦加载了某一版，它自己无法发现已有新版——宿主的 HMR
客户端只处理 `rebuilt` 帧，而携带当前版本号的 `graph` 帧被显式忽略；DSH 重启后旧版本号还会全部失效。
结果是**过期的窗口看起来完全正常**，只是永远停在旧版，不会有任何提示。

所以「设置 → 皮肤管理 → 深海女仆工坊」的面板标题带一个构建徽章：

```
深海女仆工坊 · 6 套造型 · <12 位源码指纹>
```

- **套造型**：这个包实际提供的左女仆造型数量（当前 6 套：冬日洋装 / 泳装 / 浴衣 /
  成熟-和服 / 成熟版-泳装1 / 竞速泳衣），由宿主扫描 `assets/maid-left/*` 得到，不会与目录脱节。
  看到 `1 套造型` / `2 套造型`，说明该窗口跑的是旧包。
- **12 位十六进制**：该构建的源码指纹——对 `src/**` 做排序、路径与长度分帧、换行归一后的 SHA-256，
  取前 12 位。它只随源码内容变化、不随时间变化，所以同一个构建在任何机器上都是同一个值，并且
  `lib/` 的重新构建是可复现的（用时间戳会让每次重建都不同于已提交的产物）。

标题**没有** `· N 套造型 · …` 这一段，就说明那个窗口还没有加载这一版：刷新该窗口即可；若刷新无效，
用 `Ctrl+N` 新开一个窗口对比，确认是窗口陈旧还是别的问题。

`scripts/write-skin-build-id.mjs` 生成该常量；`npm run build` 会在 `tsdown` **之前**先跑它。
`tests/build-id.spec.ts` 会重新计算一次指纹并与包内常量比对，因此「改了 `src/**` 却忘了重新构建」
会直接让测试失败，而不是让徽章谎报内容。
## 造型目录：新增一套造型不用改代码

```text
maid-atelier/assets/
├── maid-left/              左女仆
│   ├── maid/               身份参考（无工作状态，不进下拉）
│   ├── swimsuit/           泳装（分体）
│   ├── winter/             冬日洋装（默认）
│   ├── yukata/             浴衣（夏日祭）
│   ├── 成熟-和服/          2026-10-09 新增
│   ├── 成熟版-泳装1/       2026-10-09 新增
│   └── 竞速泳衣/           2026-10-09 新增
└── maid-right/             右女仆图层（主图 / vision）
```

每个造型文件夹放五张图，**文件名里带工作状态即可**：

| 状态 | 触发时机 |
|---|---|
| `idle` | 空闲 |
| `think` | 推理行仍在流式输出 |
| `tool` | 工具 / 命令行尚未结算 |
| `write` | 助手文本仍在到达 |
| `error` | 本轮出错或被中断 |

命名接受两种约定：`idle.webp` 这样最简的，或仓库里现有的
`maid-atelier-maid-left-winter-idle-v1.webp` 这种冗长形式。扫描按 `-` 分隔的
**整词**匹配，所以 `toolbox.webp` 不会被误认成 `tool`；`maid/` 因为没有五态，
不会被当成造型。

新增一套造型：

```sh
mkdir -p assets/maid-left/myoutfit
cp idle.webp think.webp tool.webp write.webp error.webp assets/maid-left/myoutfit/
```

刷新页面即可，设置里的「左女仆造型」会多出一项——未登记的 id 直接显示文件夹名，
不需要先在代码里登记。宿主每 5 秒重读一次清单，所以窗口开着时新增也会自动出现，
连刷新都不必。

**为什么是这个设计**：立绘原先以 base64 内嵌、造型 id 是 TS 联合类型，于是
「加一套造型」实际要动四处——丢图、重跑生成脚本、改联合类型和映射表、重新构建。
改成宿主扫盘后文件夹名就是造型 id，加造型＝加文件夹。代价写在下面。

### 这个设计的代价

- 立绘**不再随 bundle 自包含**，而是从 DSH 自己的本机 HTTP 服务取；`package.json`
  的 `files` 必须包含 `assets/maid-left` 与 `assets/maid-right`，否则装好后磁盘上
  没有图，宿主会扫到空。
- 两条路由注册在裸 `webServer` 上，`exact` 与更长的 `prefix` 会**绕过 DSH 的
  `/api` 认证围栏**。这是必需的——`<img src>` 带不了请求头——所以这两条路由保持
  只读、不收请求体、不收查询参数，并把路径解析限制在立绘根目录内。
- 装饰素材（宫殿背景、对话框花边、图标）仍内嵌。右女仆的四张会话状态立绘
  （思考 / 完成 / 出错 / 冬日）也仍内嵌，因为它们在 `assets/` 下没有对应文件。

## 开发与构建

皮肤工程脚手架(目录模板、`tsdown.client.ts` 构建预设、`dsh-skin-new` 脚手架、皮肤中心与切换脚本)来自 [zhu1090093659/dsh-web-ui](https://github.com/zhu1090093659/dsh-web-ui)(作者:Solitude)——**本仓库只分发皮肤成品(含预构建 `lib/`),不包含脚手架**。开发构建请在该仓库的 `skins/maid-atelier/` 目录进行:

```sh
cd <dsh-web-ui>/skins/maid-atelier
pnpm build          # tsdown 构建 lib/index.js（宿主半身）与 lib/client.js
pnpm test           # apply.spec.ts 行为测试
```

构建产物 `lib/` 提交回本仓库即完成一次皮肤更新。

立绘本身不进构建：`src/index.ts`（宿主半身）运行时扫描 `assets/maid-left/*`
并把清单发给浏览器，所以换图或加造型不需要重新构建。只有改代码才要重建。
重新标定一套立绘（绿幕抠像、去绿边、统一像素高）才需要跑
`python scripts/build-maid-left-state-art.py`，它只写 WebP，不再生成 TS 模块。
